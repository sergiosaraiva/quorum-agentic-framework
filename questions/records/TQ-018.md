EXAMPLE RECORD (invented "Acme Orders" domain).

## Question

The Quick Reference of `.claude/skills/backend/SKILL.md` requires every endpoint to declare `.Produces<T>` for each response shape or to return `Results<...>` typed results. The landed `MapOrdersEndpoints` in `src/Api/Features/Orders/OrdersEndpoints.cs` returns untyped `Results.Ok`, `Results.NotFound`, `Results.Created` and `Results.ValidationProblem`, so the OpenAPI metadata does not describe its responses and the handlers are harder to unit test. Non-blocking: the endpoints work and are covered by integration tests. Which way is the conflict resolved?

## Options

1. Migrate the Orders endpoints to `TypedResults` with `Results<Ok<T>, ValidationProblem>` (and the other shapes each handler returns), the form Microsoft recommends for OpenAPI metadata and testability (recommended).
2. Keep the untyped results and soften the skill rule to say that `.Produces<T>` metadata is enough where a handler returns `IResult`.
