## Question

`.claude/settings.json` allows agents to edit `scripts/**` without a prompt and also allow-lists commands that run those scripts (`python3 scripts/ai_review_local.py`, `python3 scripts/framework_lint.py`, `python3 scripts/kb/search.py`, `python3 scripts/kb/check_chunks.py` (and the `scripts/kb` modules they import), `python3 -m unittest`, plus the two already accepted in OD-023). An edited script then runs unprompted. Non-blocking: changes reach the integration branch only through a reviewed pull request. The same holds for allow-listed build, test and audit commands that run arbitrary code without editing a script (`dotnet build -p:PreBuildEvent=<cmd>`, `npm audit fix --registry`). That no-edit route is partly mitigated: `ask` rules cover the common property, logger and `npm audit fix` forms and the guard blocks build-event properties, but glob rules cannot cover every MSBuild switch spelling. A separate edit route remains: `Edit` on `src/**` is allowed and `dotnet build` runs MSBuild targets from a project file, so an edited `*.csproj`, `*.props` or `*.targets` runs code unprompted. Decide two things: whether to gate or accept the script edits, and whether to gate or accept the project-file edit route.

## Options

1. Add `Edit(./scripts/ai_review_local.py)`, `Write(./scripts/ai_review_local.py)` and the same two for `scripts/framework_lint.py` to `ask`, add `ask` rules for edits to `*.csproj`, `*.props` and `*.targets`, and record what remains (other MSBuild spellings) as an accepted risk in an OD that extends OD-023 with an expiry (recommended).
2. As option 1 for the scripts, but accept the project-file edit route as a risk with an expiry instead of adding the `ask` rules.
3. Record all of it as an accepted risk in an OD extending OD-023, with an expiry and no new `ask` rules.
4. Remove the script commands from the allow list; gate or accept the project-file route separately.

## Answer

Option 1, decided by the tech lead on 2026-11-27, widened after review. `ask` rules for `Edit` and `Write` of any top-level `./scripts/*.py` and `./scripts/*/__init__.py` (Python puts the script directory first on `sys.path`, so a new `scripts/json.py` or a package `scripts/json/__init__.py` would hijack the gate scripts) and of `./**/*.*proj`, `./**/*.props`, `./**/*.targets`, `./**/*.rsp` (MSBuild auto-loads `Directory.Build.rsp`) and `./**/*.user` (an auto-imported `.csproj.user`). These replace the two gate-script rules and `*.csproj`. The Bash guard also asks before shell output redirection except to `/dev/null`, fd dups or paths outside the repository (Claude Code does not check redirect targets against Edit ask rules), and the gate scripts `ai_review_local.py`, `framework_lint.py` and `coverage_changed.py` and the KB scripts `check_chunks.py`, `search.py` and `mcp_server.py` drop their own directory from `sys.path` (the KB scripts load `lib` and `backends` by path). Only `Edit(path)` rules take effect; the `Write(path)` twins are inert. The remainder is an accepted risk with an expiry, recorded in OD-032.
