EXAMPLE RECORD (invented "Acme Orders" domain).

## Decision

The VS-005 migration `AlignOrderStatusesToBc001` stays a single step. Mapping: `open` -> `draft`, `paid` -> `paid`; a `cancelled` row stops the migration (BQ-009 stays open). New orders default to `draft`. The lossy Down (draft and placed -> open; paid, shipped and closed -> paid) is accepted. Deploy order: apply the migration first, then start the new API. An adopter that runs old and new API instances side by side against one database must use a two-step rollout instead (TQ-010 option 4).

## Context

Decided on 2026-11-20 by the owner, who holds both the product owner and the tech lead roles (as in OD-004), in answer to TQ-010. The lock and row-count assumption in TQ-010 stands as written: the migration still needs review before a shared environment (Immutable Rule 2).
