EXAMPLE RECORD (invented "Acme Orders" domain).

## Question

BC-001 defines five states (draft, placed, paid, shipped, closed). The landed VS-001 code and its database check constraint allow only open, paid and cancelled (src/Infrastructure/Persistence/Configurations/OrderConfiguration.cs, status check). A status filter needs one agreed vocabulary. Is the code to be aligned to BC-001 (a VS-001 follow-up migration), or is BC-001 out of date for this phase?

## Options

1. Treat BC-001 as the truth and align the code in a VS-001 follow-up before VS-004 R2 (recommended: the KB is the grounding source; the filter then lists the BC-001 states).
2. Keep open/paid/cancelled and record an OD plus a BQ to correct BC-001 (only if the owner confirms the simpler lifecycle).
3. Filter on the code values now and migrate later (rejected: bakes a known conflict into a public contract).

## Answer

Align the code's order statuses to BC-001 (draft, placed, paid, shipped, closed) in a separate VS-001 follow-up, tracked as VS-005 (option 1). Answered by the tech lead on 2026-11-19. Recorded as OD-004. Consequence: the VS-004 status filter waits for VS-005.
