EXAMPLE RECORD (invented "Acme Orders" domain).

## Question

POST /api/orders with a customerName containing a NUL character (U+0000) probably returns 500, because PostgreSQL rejects 0x00 in text; the GET filter now rejects NUL with a 400 but the create path was not changed. Confirmed by reading the code: `CreateOrderRequest` has only Required and StringLength on `CustomerName`, with no NUL check. Not confirmed: the 500 itself, because it was not run.

## Options

1. Reject NUL in the create validation too, as a VS-001 follow-up (recommended: same rule as the GET filter, small change).
2. Strip NUL silently (changes stored data without telling the caller).
3. Leave as is (a 500 on bad input).

## Answer

Decided in OD-020: option 1, reject NUL in the create validation. The owner (product owner, tech lead and privacy roles) answered on 2026-11-20.
