EXAMPLE RECORD (invented "Acme Orders" domain).

## Question

BC-001 lists five states (draft, placed, paid, shipped, closed) and says an order can be cancelled only in draft or placed, but it names no state or flag for an order that has been cancelled. The pre-VS-005 code allowed a `cancelled` status. After VS-005 there is no such value. How is a cancelled order recorded: a sixth state, a flag or timestamp on the order, the order is deleted, or cancellation is out of scope for this phase?

## Options

1. Add a `cancelled` state to BC-001 (a chunk edit through `documentation-curator`) and to the code vocabulary in a follow-up (recommended if cancelled orders must stay visible and filterable).
2. Record cancellation as a timestamp and acting user on the order, keeping the status at its last state (BC-001 already says state changes are recorded with a timestamp and acting user).
3. Cancelled orders are removed; no state is needed.

## Working assumption (non-blocking)

No cancellation feature exists in the code: nothing writes `cancelled` (the API creates orders and reads them only). The VS-005 migration therefore refuses to run if it finds a `cancelled` row, so no data is lost or relabelled by guess; it stays open until this question is answered. VS-004 R2 filters only on the five BC-001 states.
