EXAMPLE RECORD (invented "Acme Orders" domain).

## Question

BQ-003 option 1 (decided in OD-002) says the status filter is an exact match on one value. Neither it nor BC-001 says how the value is written. Which input rules apply: lowercase only and case-sensitive, surrounding whitespace trimmed, a blank value meaning no filter?

## Options

1. Exact, lowercase, case-sensitive match on the values the API returns; surrounding whitespace trimmed; empty or blank means no status filter; anything else, including a repeated or comma-joined value, gives 400 (recommended: current behaviour, same blank handling as the other filter parameters).
2. Accept any casing (`PAID` matches `paid`): friendlier, but a second spelling of the contract.
3. Treat a blank value as 400 (stricter, differs from the other filters).

## Working assumption (non-blocking)

Option 1, as built and tested in VS-004 R2 (`OrderListFilter.Parse`, criterion 9).

## Answer

Decided in OD-021: option 1, the behaviour as built in VS-004 R2. The owner (product owner, tech lead and privacy roles) answered on 2026-11-20.
