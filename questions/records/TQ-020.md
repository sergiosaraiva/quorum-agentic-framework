## Question

`.claude/settings.json` allows agents to edit `scripts/**` without a prompt and also allow-lists commands that run those scripts (`python3 scripts/ai_review_local.py`, `python3 scripts/framework_lint.py`, `python3 scripts/kb/search.py`, `python3 scripts/kb/check_chunks.py` (and the `scripts/kb` modules they import), `python3 -m unittest`, plus the two already accepted in OD-023). An edited script then runs unprompted. Non-blocking: changes reach the integration branch only through a reviewed pull request. The same holds for allow-listed build, test and audit commands that run arbitrary code without any edit (`dotnet build -p:PreBuildEvent=<cmd>`, `npm audit fix --registry`). That first route is now mitigated by `ask` rules (dotnet property and logger overrides, `npm audit fix`) and a guard rule in `.claude/hooks/guard_bash.py` (build-event overrides). The edit-then-build route remains: `Edit` on `src/**` is allowed and `dotnet build` runs MSBuild targets from a project file, so an edited project file runs code unprompted. Accept that remaining route, or gate it (for example `ask` on edits to `*.csproj`, `*.props` and `*.targets`)? Accept the risk of the script edits, or gate edits to these scripts?

## Options

1. Add `Edit(./scripts/ai_review_local.py)`, `Write(./scripts/ai_review_local.py)` and the same two for `scripts/framework_lint.py` to `ask`, and record the rest as an accepted risk in an OD that extends OD-023 with an expiry (recommended).
2. Record all of it as an accepted risk in an OD extending OD-023, with no new `ask` rules.
3. Remove the script commands from the allow list.
