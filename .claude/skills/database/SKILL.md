# Creating EF Core Entities

Design Principles: `.claude/agents/_SHARED-PATTERNS.md`. If the project keeps a data-model conventions doc (for example `docs/datamodel/CONVENTIONS.md`, adopter-supplied: not shipped with the template, create it when the data model needs one), it is authoritative and this skill shows how to express it in EF Core.

## Quick Reference

- Entities are plain POCOs (no EF attributes) in `src/Infrastructure/Persistence/Entities/<Schema>/`; mapping lives in `IEntityTypeConfiguration<T>` under `Persistence/Configurations/<Schema>/`
- `UseSnakeCaseNamingConvention()` once, in a shared `ConfigureCore` used by the API, tests and CLI tools. Never hand-roll casing
- Tables are singular, equal to the CLR type name, and live in a bounded-context schema, never `public`. Pin the EF migrations-history table to its own schema
- Primary key `id uuid`, app-generated with `Guid.CreateVersion7()`. A very high-volume internal fact table may use `bigint GENERATED BY DEFAULT AS IDENTITY`
- Foreign keys are `<referenced_table>_id`; a natural-key text code is `<referenced_table>_code`
- Constraint/index names over 63 bytes get a hand-picked name (`HasConstraintName`, `HasDatabaseName`). Index only what a real query needs; EF does not add unlisted FK indexes if you remove `ForeignKeyIndexConvention`, so decide deliberately
- Money, rates and quantities: `numeric(p,s)` via `HasPrecision` (for example `numeric(19,4)` amounts, `numeric(19,8)` rates). Never `float`, `double` or `money`
- Timestamps are `timestamptz` (`DateTimeOffset`); dates without time are `date` (`DateOnly`)
- Closed code-owned enum: C# enum + a shared string converter + a `CHECK` with the same literals. Data-owned or extensible set: a lookup table with a natural `code` key. Avoid native PostgreSQL enums (values cannot be dropped, `ADD VALUE` conflicts with same-transaction use)
- Audit columns `created_at`, `created_by`, `updated_at`, `updated_by` are set by a `SaveChanges` interceptor, never by callers. Map `xmin` as the concurrency token (`.IsRowVersion()`)
- No blanket soft delete. Where required: `deleted_at` / `deleted_by`, a partial unique index `WHERE deleted_at IS NULL`, a named EF query filter, never `is_deleted boolean`
- Period-valid data: `daterange valid_during` + `EXCLUDE USING gist` (`btree_gist`), end-dated instead of updated in place
- `DeleteBehavior` per relationship: `Cascade` only when the child is meaningless without the parent, else `Restrict` or `SetNull`
- Per-customer settings: one typed single-row `<area>_setting` table, not key/value. Deploy-varying values stay in Options/Helm (`creating-configuration-options`)

## Multi-tenancy (optional, decide once)

| Model | Rule |
|-------|------|
| Database per tenant | No `tenant_id` column, no tenant query filter. Isolation is the connection string, resolved once per DI scope by an `ITenantConnectionResolver` from the validated token claim, never from request input. Background work takes the tenant only from the message envelope, one scope per message. Fail closed when no tenant resolves |
| Shared database | `tenant_id` on every tenant table, a global query filter, tenant-leading indexes, and a test that proves cross-tenant reads return nothing |
| Single tenant | Neither. Do not add either speculatively |

Cached tenant data uses a tenant-prefixed key (`implementing-caching-strategies`); logs carry the tenant in a logger scope (`implementing-observability`).

## Example

```csharp
public enum OrderStatus { Draft, Submitted, Paid, Cancelled }

public sealed class Order
{
    public Guid Id { get; set; }                       // uuid v7, app-generated
    public Guid CustomerId { get; set; }
    public OrderStatus Status { get; set; } = OrderStatus.Draft;
    public decimal TotalAmount { get; set; }
    public DateTimeOffset CreatedAt { get; set; }      // interceptor-set
    public Guid CreatedBy { get; set; }
    public DateTimeOffset? UpdatedAt { get; set; }
    public Guid? UpdatedBy { get; set; }
    public uint Version { get; set; }                  // xmin
}

public sealed class OrderConfiguration : IEntityTypeConfiguration<Order>
{
    public void Configure(EntityTypeBuilder<Order> builder)
    {
        builder.Metadata.SetSchema("sales");           // table name comes from the singularizing convention
        builder.HasKey(o => o.Id);
        builder.Property(o => o.Status).HasConversion(new UpperSnakeEnumConverter<OrderStatus>());
        builder.Property(o => o.TotalAmount).HasPrecision(19, 4);
        builder.Property(o => o.Version).IsRowVersion().HasColumnName("xmin").HasColumnType("xid");
        builder.ToTable(t => t.HasCheckConstraint("ck_order_status",
            "status IN ('DRAFT','SUBMITTED','PAID','CANCELLED')"));
        builder.HasIndex(o => new { o.CustomerId, o.Status }).HasDatabaseName("ix_order_customer_id_status");
    }
}
```

Interceptor: a `SaveChangesInterceptor` walks `ChangeTracker.Entries<IAudited>()` and stamps `Created*` on `Added`, `Updated*` on `Modified` from `TimeProvider` and the current principal. A `CHECK (created_at > '2000-01-01')` makes a missed stamp fail.

## Quality Checklist

- [ ] snake_case, singular, schema-qualified; UUIDv7 key; `HasPrecision` on every decimal
- [ ] Enum is converter + `CHECK`, or a lookup table; no native enum
- [ ] Audit columns interceptor-set; `xmin` concurrency token on mutable aggregates
- [ ] Every index names a real query; no speculative columns or generic `jsonb` blobs
- [ ] Delete behaviour chosen per relationship; soft delete only when required
- [ ] Tenant model decided and applied consistently

## Common Mistakes

| Wrong | Correct |
|-------|---------|
| `float`/`double` for money | `numeric` with `HasPrecision` |
| `Guid.NewGuid()` keys | `Guid.CreateVersion7()` |
| Callers set `CreatedAt` | Interceptor |
| `is_deleted boolean` | `deleted_at` + partial unique index |
| `CREATE TYPE ... AS ENUM` | `text` + `CHECK`, or a lookup table |
| Per-entity enum dictionaries | One shared converter |
| Everything in schema `public` | One schema per bounded context |
