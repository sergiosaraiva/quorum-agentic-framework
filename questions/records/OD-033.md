## Decision

Risk: `.claude/hooks/guard_bash.py` is a best-effort second layer behind the `deny` list, not a sandbox. It asks before shell output redirection except to exactly `/dev/null`, a pure file-descriptor dup or close (`2>&1`, `>&2`, `>&-`), or a path outside the repository that is not under `/dev/` or `/proc/`. Targets inside the repository, dynamic targets (`$VAR`, backtick, `~`, globs, brace expansion `{`), relative targets after `cd`, `pushd` or `popd`, and any other `/dev/*` or `/proc/*` path ask (an fd reopen such as `3<file >/dev/fd/3` overwrites an existing file). Substitutions inside arithmetic spans and unquoted heredoc bodies are inspected too. Deny wins over ask. Its module docstring ("Known gaps") lists commands it can miss: runtime-built commands, commands inside arithmetic spans, some wrapper long options, some git configuration routes and uncommon interpreters. Residual: commands that write files themselves (not through a shell redirect), for example dotnet `-bl:`, `-flp:logfile=` and `--artifacts-path`, and `dotnet format`, are not gated, and such a write could even overwrite the guard itself (a failing hook fails open). Owner: the tech lead accepted this list on 2026-11-27 (TQ-021, option 1). Mitigation: the `deny` list and the permission prompt in default mode; never rely on the guard in `bypassPermissions` or auto mode. At expiry (2027-05-27), or earlier when Claude Code's sandbox is enabled for the project: revisit; renew with a new OD or fix the gaps and close this record.
