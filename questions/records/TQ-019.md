## Question

On `pull_request`, GitHub runs `.github/workflows/ai-pr-review.yml` from the PR's merge ref, so a same-repo branch can edit the workflow itself and the edited copy runs with repository secrets before anyone reviews it (CODEOWNERS and branch protection only gate the merge). A repository secret `ANTHROPIC_API_KEY` is therefore readable by anyone with push access. Non-blocking: the review job is skipped without the key. Where does the key live?

## Options

1. An environment secret on a protected environment with required reviewers, and `environment: <name>` on the review job (recommended). Not wired in the template because it needs the environment to exist and was not exercised in CI (since wired; see Answer). The `gate` job's key check must move into the review job (or the gate job must use the same environment), otherwise the key reads as empty there and the review is silently skipped; enable "prevent self-review" on the environment.
2. Keep the repository secret and accept that anyone with push access can read it.
3. Option 1 plus further hardening, after one test run: set `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB: "1"` on the review step, with a step that installs bubblewrap (the action installs it only for `allowed_non_write_users`, so without that step the setting could break the review step). It was tried in the workflow and reverted because it was untested.

## Answer

Option 1, decided by the tech lead on 2026-11-27, refined the same day. The review runs only when the repository variable `AI_REVIEW_ENABLED` is `true`. Otherwise the review job is skipped entirely, the gate prints a notice, and no environment, deployment or approval wait is created. When enabled, the review job in `.github/workflows/ai-pr-review.yml` has `environment: ai-review` and the key is an environment secret there. Its first step checks for the key (the `gate` job cannot see environment secrets); if the review is enabled but no key exists, the later steps are skipped with a notice, so the check is green, no model call is made and no round is recorded.

Protection needs required reviewers and "prevent self-review" on `ai-review`. GitHub offers required reviewers on public repositories on all plans, but on private or internal repositories only on GitHub Enterprise (source: https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments). On other plans the environment does not protect the key: the exposure equals that of a repository secret. Approvers approve only `pull_request` runs of `ai-pr-review.yml` and reject any other workflow or event that requests `ai-review`, and any run that changes `.github/**`. On GitHub Free private repositories environment secrets are unavailable (they need Pro, Team or Enterprise), so the only option there is a repository secret, readable by anyone with push access. Set up in this order: create the environment `ai-review` (required reviewers, prevent self-review, administrator bypass off), add the environment secret, then set `AI_REVIEW_ENABLED=true` last; if the review runs first, GitHub creates `ai-review` automatically and unprotected. Delete any repository- or organization-level `ANTHROPIC_API_KEY` once the environment secret exists. With required reviewers every run waits for approval; to switch the review off, unset `AI_REVIEW_ENABLED`. Option 3 (subprocess environment scrub plus bubblewrap) is deferred until after the first successful CI run.
