EXAMPLE RECORD (invented "Acme Orders" domain).

## Question

Search and list endpoints have no rate limit or query timeout. An ILIKE '%term%' search costs two sequential scans per request (measured about 0.4-1.6 s at 1M rows, linear in rows). Which per-user rate limit and command timeout apply, and at what row count or p95 do we add a pg_trgm index with a minimum term length?

## Options

1. ASP.NET Core built-in rate limiter per user plus a command timeout from Options now; trigram GIN index (reviewed migration) plus a minimum term length of 3 when the order table exceeds about 500k rows or p95 exceeds 300 ms (recommended: built-ins first, index only on measured need).
2. Rate limit and timeout only, never an index (cost stays linear in rows).
3. Add the trigram index and the term-length rule now (a migration and an extension before any measured need).

## Answer

Decided in OD-018: option 1, built-in rate limiter per user and command timeout now; trigram index and minimum term length only above about 500k rows or p95 300 ms. The owner (product owner, tech lead and privacy roles) answered on 2026-11-20.
