EXAMPLE RECORD (invented "Acme Orders" domain).

## Decision

Search and list endpoints get the ASP.NET Core built-in rate limiter, partitioned per user, and a database command timeout read from Options now (TQ-007 option 1). The limit and timeout values are Options, not literals (Design Principle 3); this record does not fix the timeout number (see OD-025). The default of 60 requests per 60 seconds was confirmed by the owner on 2026-11-20 (the limit and window stay Options). A trigram GIN index (a reviewed migration, Immutable Rule 2) and a minimum search-term length of 3 are added only when the order table exceeds about 500,000 rows or the p95 latency of the search exceeds 300 ms. The follow-up code is tracked in the slice follow-up PR; this record does not claim it is done. This is a decision, not an acceptance of the risk (no `accepted_risk`).

## Context

Decided on 2026-11-20 by the owner, who holds the product owner, tech lead and privacy roles (as in OD-004), in answer to TQ-007, as tech lead.
