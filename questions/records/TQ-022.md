## Question

The required local review (`python3 scripts/ai_review_local.py --require`) accepts only the base that the remote HEAD (`<remote>/HEAD`, for example `origin/main`) points at, at the point the branch was cut. Without `<remote>/HEAD` it refuses and says to run `git remote set-head <remote> -a`; it also refuses when `<remote>/HEAD` points at the branch's own ref or HEAD is detached. A stacked rung (a rung built on an unmerged parent branch) or a repository whose integration branch is not the remote default therefore cannot use its parent or its own integration branch as `--base` under `--require`. Non-blocking: such branches run the gate with `--base origin/main`. May a stacked parent or a non-default integration branch anchor the base?

## Options

1. No (recommended, applied). Such branches run the gate with `--base origin/main`, a wider review (parent plus child). A repository whose integration branch is not `main` changes the default with `git remote set-head <remote> <branch>`. A parent base remains fine without `--require`, which is not the gate.
2. Accept any remote-tracking base other than the branch's own. This reviews only the child rung, but it reopens the route of pushing an older commit under another name and using it as the base to narrow the review.

## Answer

Option 1 confirmed by the tech lead on 2026-11-27 (already applied in the script and the docs): a stacked parent or a non-default integration branch does not anchor the `--require` base; such branches run the gate with `--base origin/main`.
