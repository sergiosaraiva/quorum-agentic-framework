EXAMPLE RECORD (invented "Acme Orders" domain).

## Question

OD-012 requires that the customer name in the query string of `GET /api/orders` does not reach logs. The API logs nothing of it, but the request URL can also land in a reverse proxy access log, OpenTelemetry `url.query` attributes and PostgreSQL statement logs (parameters). Which layer enforces the redaction (proxy configuration, telemetry processor, PostgreSQL `log_statement` and parameter logging settings), and who verifies it before the first deployment target is chosen? No deployment configuration exists yet.

## Options

1. Record the redaction as a requirement of the deployment TQ and verify it in each layer when the target is chosen (recommended).
2. Move the search to POST so the term leaves the URL (rejected earlier in OD-012).
3. Add an application-level telemetry processor that strips `url.query` now.

## Answer

Decided in OD-027: option 1. The redaction of the customer-name query value (and bound parameters) is enforced per deployment target in infrastructure code across proxy and access logs, telemetry `url.query` and database log settings; it is a required item of the infrastructure readiness checklist, verified by the infrastructure review before the first deployment, and stays a deployment follow-up (a TQ at target selection) until a target is chosen. Answered on 2026-11-20 on the owner's delegation to the session's recommendation.
